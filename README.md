# AI Leader ID · inVision U

Работающее fullstack-приложение: пять учебных проб до регистрации, личное пространство, заявка с приватными материалами, отдельная языковая проверка и рабочее место комиссии. Готовность, мотивация и опыт не сводятся в общий балл. Решения сохраняются только от имени сотрудника.

## Личный маршрут и проекты · 17 сентября 2026

«Мой путь» (`/my`) предлагает конкретное действие новому гостю, продолжает точную сохранённую попытку и показывает личную коллекцию «Мои проекты». Запрос сотрудника, приглашение или действие по заявке имеют приоритет над мастерскими. Комплектность заявки использует те же обязательные условия, что серверная отправка; учебные работы и исследовательское согласие в неё не входят.

На существующей базе выполните `npm run db:migrate`: добавочная миграция `20260917120000_candidate_journey` сохраняет прежние попытки и версии. Не запускайте повторный seed и не сбрасывайте базу. Для локальной проверки используйте `AUDIO_WORKER_ENABLED=false OPENAI_API_KEY=''`.

1. Откройте `/my` без аккаунта → «Проверить маршрут сервиса». Поднимите выбор мастерской перед личными данными, отключите обязательный телефон, сохраните результат. Неполный вариант сохраняется как черновик и не выдаёт «Первую работу».
2. В результате видны сама работа, изменения и сохранённый разбор по правилам упражнения. Выберите версию; сравнение «До / После» показывает одно читаемое превью, в том числе на телефоне. Доработка не объявляется улучшением автоматически.
3. После завершённого маршрута добровольно доступно бронирование оборудования. Камера занята в 16:00, диктофон недоступен в 17:00; нужно учесть свободное время, контакт и понятное подтверждение. Исходная работа, её обратная связь, отдельная попытка и использованные подсказки сохраняются.
4. Регистрация возвращает к конкретному результату и сохраняет владельца гостевых работ. Вход в существующий аккаунт объединяет его работы с собственными гостевыми попытками без копирования версий. Просмотр и доработка до регистрации доступны.
5. Выполните другую мастерскую → `/my` → «Мои проекты». У каждой работы своё превью, версии, разбор и переход к направлению. Интерес сохраняется только кнопкой кандидата. Он не меняет программу заявки.
6. Сохраните черновик заявки. В коллекции выберите конкретную версию, раскройте связь с направлением и заявкой, подтвердите передачу. После отправки новые версии не меняют snapshot, человеческое решение или опубликованное сообщение.

Четыре приватные отметки вычисляются сервером из `ProjectAttempt` / `AttemptVersion`: завершённая авторская работа; содержательная переработка; две разные мастерские; завершённое бронирование с завершённой исходной работой. Каждая ссылается на подтверждающую версию и несёт версию правила (2). Пустое действие, переименование, форматирование, согласия, язык и частота входа не учитываются. Старые версии с `ruleVersion=0` проверяются по явным условиям упражнений, исходная версия 0 не считается работой. Отдельного сервиса наград нет; комиссия не получает эти отметки.

Повтор сохранения с тем же ключом не создаёт новую версию. При конфликте сервер не перезаписывает работу: введённый вариант остаётся в форме, можно открыть параллельную версию и явно сохранить свой вариант новой записью с исходной базой сравнения. При удалении работы проекция отметок пересчитывается по оставшимся работам; связанная дополнительная попытка удаляется каскадно, ссылок на удалённые материалы не остаётся. Пользовательского интерфейса удаления в этом задании не добавлено.

В локальной базе есть новая вымышленная история **Мира Тестова** (`origin=JOURNEY_BROWSER_QA`): три работы, четыре отметки, явный интерес к инженерии, заявка на цифровые продукты с выбранной версией 1, опубликованное уточнение и ответ. Это результат текущего прохода, не seed. Снимки и фактическая проверка перечислены в `QA.md`.

## Рассмотрение и публикация · 17 сентября 2026

Завершён локальный путь одной заявки: сводный профиль → карта девяти областей → уточнение → подготовка и отдельная запись встречи → внутреннее решение → предпросмотр → публикация в приложении → «Мой путь». Внешний AI для этого пути не требуется. Подробные проверки и ограничения — в актуальном разделе `QA.md`.

Модель рассмотрения добавлена миграцией `20260917090000_review_publication`; на существующей базе применяйте неприменённые добавочные миграции командой `npm run db:migrate`. Сброс базы и повторный seed не нужны. Для этого сценария запускайте приложение и тесты с `AUDIO_WORKER_ENABLED=false OPENAI_API_KEY=''`; `audio:live` не используется.

1. Новый кандидат сохраняет поля и разрешённые материалы, проверяет обзор и явно отправляет заявку. При отсутствии документа доступно существующее пояснение; ссылка на видео остаётся ссылкой, её доступность не считается проверенной.
2. Сотрудник входит в `/admissions`, открывает заявку и сверяет три блока профиля. В «Карте проверки» отдельно сохраняет связанные источники, просмотр, достаточность, согласованность, пробел и вопрос. Оценка проявления — отдельное человеческое действие по настроенной версии рубрики, без общего балла.
3. В источнике можно отметить точный фрагмент и личное действие, связать его с существующим эпизодом. Дубли описаний объединяются только явно, с причиной; исходные записи сохраняются.
4. Во вкладке «Решение и публикация» сотрудник сохраняет внутренний этап. Запрос кандидату готовится отдельно: наблюдение, уточнение/развитие, следующий шаг и источники. Публикация требует предпросмотра и отдельного подтверждения. Сообщение появляется внутри приложения; email не отправляется.
5. Ответ кандидата в переписке становится новым источником. Исходная отправленная версия не меняется; прежние выводы помечаются для сверки. Запрос исправления факта также хранится отдельно.
6. При решении «Интервью» создаётся существующая запись встречи. План ATOLA содержит пять обязательных секций и редактируемые дополнительные вопросы из шаблонов по явно отмеченному пробелу. «Сохранить подготовку» не завершает встречу. После разговора сотрудник отдельно вводит фактическую дату, ответы пяти секций, наблюдение, итог и подтверждение.
7. После сверки новых материалов сотрудник сохраняет новое решение и публикует обратную связь. История решений, подготовки, результатов и публикаций остаётся доступна. Кандидату не передаются внутренние основания, оценки и результаты интервью.

В текущей локальной базе сохранена новая вымышленная история **Леи Соколовой** (`origin=BROWSER_REVIEW_QA`), которой нет в seed: три решения, два опубликованных сообщения, ответ-уточнение и отдельная завершённая тестовая встреча. Найдите её по имени в очереди. Доступ к тестовому аккаунту записан только в игнорируемом `.local/review-browser-account.json`.

Сборщик фактов находится в `src/lib/data.ts`, проверка версий и серверные операции — в `src/lib/review-service.server.ts`, схемы пяти секций, ограничений и небольшого набора вопросов — в `src/lib/review-contract.ts`. Используются прежние роли, `/api/action`, PostgreSQL, сообщения, файлы и версии; новый backend или framework провайдеров не добавлен.

## Запуск

Нужны Node.js 20.9+ и PostgreSQL с `initdb`, `pg_ctl`, `psql`, `createdb` в PATH. На этой машине проверены Node 20.19.5 и PostgreSQL 18.

```sh
npm ci
npm run setup
npm run dev
```

Открыть http://127.0.0.1:3000. `setup` создаёт отдельный локальный кластер в `.local/postgres`, базу `leader_id` на `127.0.0.1:55439`, применяет миграции и 12 связанных кандидатских историй. Существующие данные повторный seed не стирает. Остановка базы: `npm run db:stop`. Остановка приложения: Ctrl+C в его терминале.

Кластер слушает только loopback; локальный trust-доступ предназначен для разработки. Для своего PostgreSQL скопируйте `.env.example` в `.env`, задайте `DATABASE_URL` и выполните `npm run db:migrate`. Для внешней базы не запускайте локальный seed. В обычном окружении `ENABLE_LOCAL_SEED=false`.

Для проверки собранного приложения: `npm run build`, затем `npm start` (порт 3000 должен быть свободен). Для HTTPS задайте `APP_ORIGIN` и `COOKIE_SECURE=true`.

## Устройство

Next.js 16 App Router, React 19, TypeScript, Prisma 6, PostgreSQL, Tailwind 4 и CSS-токены. Точные версии закреплены в `package-lock.json`. Приложение не требует внешнего AI, почтового сервиса или облачного хранилища.

- `src/lib/projects.ts`: версия авторского сценария, строгая схема состояния и пять разных проверок. Пять отдельных компонентов рабочих областей находятся в `src/components/workspaces.tsx`; `ProjectEditor` отвечает за общий сценарий и сохранение.
- `src/lib/security.ts`: непрозрачная cookie-сессия с хешем в БД, scrypt для паролей, серверная роль, проверка владельца, Origin и лимит запросов.
- `src/app/api/action`: серверные операции, optimistic revision, журнал версий, отдельные разрешения и человеческие решения.
- `src/app/api/files`: проверка размера, MIME и сигнатуры; максимум 25 МБ на файл и 150 МБ на владельца. Бинарные оригиналы находятся в PostgreSQL. Приватная выдача с Range для аудио/видео.
- `src/lib/recording-cache.ts`: восстановление незагруженных записей из IndexedDB с ключом пользователя, заявки и вопроса. После подтверждённой привязки файла и при выходе пользователя его буфер удаляется. Выбор файла не запускает загрузку. Пробная запись остаётся локальной.
- `src/lib/ai.ts`: заменяемый серверный интерфейс для объяснения источников. Zod-ответ, проверка ID источников, тайм-аут 8 секунд, лимиты входа и 600 выходных токенов. Внешний провайдер не подключён. Контекстные подсказки сейчас детерминированно используют собственную сохранённую работу и каталог, без фиктивной генерации.
- `prisma/schema.prisma`: связанные пользователи, попытки, версии, заявки, передачи, материалы, эпизоды, источники, исправления, оценки, решения, сообщения, интервью и языковые проверки.

Отправка заявки и присоединение материалов сериализованы блокировкой её строки. Передаётся конкретная подтверждённая версия учебной работы. Отправленная заявка фиксирует поля, ID материалов и снимки передач. Уточнения добавляются отдельными записями; оценка сотрудника кандидатом не перезаписывается. Языковая проверка не изменяет лидерские оценки. Дубли источников одного проекта объединяются эпизодом.

## Технические ограничения

Это самостоятельная локальная поставка. Для реальной приёмной кампании нужны организационно утверждённые требования, роль ответственного за данные, сроки хранения, HTTPS, резервные копии и проверенный процесс выдачи доступа. Сейчас нет email verification, восстановления пароля, SSO, антивирусной обработки, квоты хранилища на всё учреждение и распределённого rate limit. Файлы хранятся в БД, не в объектном хранилище. CSP допускает inline-скрипты и eval для Next dev; перед внешним развёртыванием её нужно настроить с nonce и режимом production.

Расшифровка и содержательная сводка новых ответов подключены к серверному OpenAI API. В этой рабочей копии ключ не задан, внешние запросы не выполнялись; ручное рассмотрение работает. Это не автоматическая языковая оценка или решение о поступлении. Русский интерфейс готов; для казахского предусмотрен тип локали и словарь с fallback, полного перевода нет и неработающий переключатель не показан. Проверка в реальных мобильных Safari/Chrome и на разных микрофонах остаётся отдельной приёмкой.

Старый проект не читался, не копировался и не менялся. Push, merge и deploy не выполнялись.

## Новый аудиоответ и OpenAI

Существующая языковая проверка `/apply/english` использует AudioCapture, Recorder и текущий файловый API. Микрофон запрашивается только кнопкой; проба остаётся локальной. Запись или выбранный файл сначала доступны для прослушивания. «Подтвердить отправку записи» загружает файл и дожидается привязки к вопросу. Восстановление из IndexedDB не включает микрофон, не отправляет файл и не создаёт обработку.

Существующий `SourceProvider` в `ai.ts` отвечает на вопросы по текстовым источникам и не имеет операции распознавания файла. Для этого потока добавлен узкий серверный `AudioProvider` с двумя операциями: расшифровка и структурированная сводка. Файловое хранилище, авторизация, языковая проверка и переписка используются повторно.

1. Зарегистрируйте нового кандидата, откройте заявку и языковую проверку, подтвердите согласие на хранение аудио.
2. Сохраните основной ответ и отдельное уточнение. Завершите языковой ответ и отправьте заявку: до отправки комиссия не читает черновик.
3. При настроенном OpenAI появится отдельное, необязательное согласие `openai-audio-v1`. Сохранение согласия и запуск расшифровки — разные действия. После согласия нажмите «Подготовить расшифровку и сводку».
4. Комиссия открывает ту же карточку: оригинал, исходный текст, сводка, точные цитаты и заключение. Исправление расшифровки добавляет версию; старая сводка явно остаётся рассчитанной по исходному тексту. Можно отклонить замечание с пояснением и перейти в существующую переписку. Обработка не завершает человеческую проверку.

В текущей базе новый файловый проход: `audio.nova@candidate.local` / `AudioPath2026!`, Нова Аудио, `origin=BROWSER_AUDIO_QA`. Файлы выбраны и подтверждены через браузер; модельный результат ей не подставлялся. Отдельная подготовленная история Лины Мир (`origin=PREPARED_AUDIO_QA`, `provider=controlled-fixture`) служит только проверке интерфейса сводки на её собственных фиксированных файлах. Она не является живым результатом OpenAI и не создаётся обычным seed.

### Конфигурация

В `.env` используются только серверные переменные из `.env.example`:

- `OPENAI_API_KEY` — ключ проекта OpenAI; в клиентские переменные и Git не попадает.
- `OPENAI_TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe-2025-12-15` — завершённый WAV через `/v1/audio/transcriptions`, без подсказки ожидаемого текста, перевода и принудительного языка.
- `OPENAI_TEXT_MODEL=gpt-4.1-mini-2025-04-14` — `/v1/responses`, строгая JSON Schema, `store:false`, максимум 2400 выходных токенов.
- `AUDIO_WORKER_ENABLED=true` — обработчик запускается в Node-процессе Next через instrumentation. При выключении новые задачи не ставятся в ожидание.
- `AUDIO_DAILY_REQUEST_LIMIT=30` — общий предел зарезервированных вызовов за последние 24 часа; рабочие, контрольные и тестовые режимы считают бюджет раздельно.

После изменения конфигурации перезапустите приложение. Нужен постоянно работающий Node-процесс с доступом к PostgreSQL и установленному FFmpeg. Миграция `20260915103000_audio_processing` добавляет таблицы и два поля Material; исходная миграция и существующие записи сохранены. Для обновления: `npm run db:migrate`, `npx prisma generate`, затем запуск приложения.

Оригиналы остаются в PostgreSQL. FFmpeg проверяет декодирование и фактическую длительность 0,25–180 секунд, затем готовит моно WAV 16 кГц для провайдера. Размер исходного файла — до 25 МБ. Обычный M4A временно записывается в закрытый каталог для чтения с перемещением; файл удаляется после проверки, внешние ссылки контейнера выключены.

Задания находятся в PostgreSQL. Захват выполняется через `FOR UPDATE SKIP LOCKED`, аренда — 90 секунд с продлением каждые 10 секунд. После перезапуска просроченное задание снова доступно обработчику. Максимум три попытки на идентичную версию, пять новых заданий на кандидата за сутки; задержка повторов 15/30 секунд. Декодирование ограничено 20 секундами, расшифровка — 60, сводка — 30. На одну попытку приходится не более трёх внешних вызовов. При повторе используются уже сохранённые расшифровки. После неопределённого сетевого сбоя возможен повторный платный вызов: абсолютно однократная тарификация не обещается.

Идентичность включает языковую попытку, оба ID и SHA-256 файлов, версию задания и инструкции, провайдера и модели. Согласие проверяется при постановке и перед каждым вызовом; отзыв запрещает следующие вызовы и публикацию запоздавшего результата. Уже отправленный запрос нельзя отозвать задним числом. В OpenAI уходят только конкретные записи либо условия задания и соответствующие тексты — без остальных полей заявки, имени, контактов, школы и заметок сотрудников. Usage и ID запроса сохраняются, когда сервис их возвращает; общие логи не содержат речи.

Сервер проверяет структуру, ID источника, вопрос, версию и точное вхождение каждой цитаты. Проверка отсутствующего пункта ссылается на требование и весь соответствующий ответ, без выдуманной цитаты. Совпадение цитаты не доказывает точность интерпретации: сводка показывается для сверки человеком. Таймкоды не создаются. Лидерские оценки, решения и этап интервью не изменяются обработчиком.

Официальная документация проверена 15 сентября 2026: [Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [транскрипционная модель](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe), [текстовая модель](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [обработка данных](https://developers.openai.com/api/docs/guides/your-data), [правила использования](https://openai.com/policies/usage-policies/). `store:false` не является гарантией нулевого хранения внешним сервисом; применяются условия и фактические настройки проекта OpenAI.

### Отдельные проверки аудио

`npm test` использует изолированный провайдер и подмену транспорта в тестах; платных запросов не выполняет. Фиксированные WAV в `tests/fixtures/audio/` созданы локальной озвучкой английского текста, без чужой речи. Ожидаемый текст находится только в тестовых данных и не передаётся реальному распознавателю.

SHA-256 обоих WAV закреплены в `manifest.json`: несовпадение останавливает подготовку контрольной истории до записи в БД. Подготовленный текст не подставляется для изменённого или произвольного файла.

Для явной живой проверки после настройки ключа:

```sh
npm run audio:live -- --confirm-paid
```

Команда создаёт новую изолированную историю, использует только два включённых файла, делает максимум два вызова расшифровки и один вызов сводки, без автоматического повтора. Состояние и метаданные сохраняются в БД с режимом `LIVE_CHECK`; обычный обработчик их не подхватывает. Локальный отчёт: `.local/audio-live-result.json`. При отсутствии ключа команда завершается до создания истории и до запросов. Эта защитная ветка проверена; живой прогон не выполнялся.

Для контролируемого виртуального входа: `npm run audio:virtual`, затем `http://127.0.0.1:4177`. Стенд вне продуктовых маршрутов подаёт WAV через Web Audio в настоящий MediaRecorder с тем же AudioCapture. Он не вызывает getUserMedia и не захватывает помещение. Приложение и этот стенд останавливаются Ctrl+C в соответствующих терминалах.
