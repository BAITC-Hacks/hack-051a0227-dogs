## AI-скоринг и всплывающий Vision Desk · 25 сентября 2026

В карточке остаётся один основной **AI-скоринг**. Отдельные блоки Vision Desk и служебного AI-профиля убраны. «Цитата и основание» открывает рассмотренный фрагмент, объяснение и версию; перед показом сервер заново проверяет сотрудника, заявку и доступность источника. Полный материал открывается в прежней соседней панели. Кнопка со знаком Vision у имени вызывает чат по кандидату. В очереди чат использует выбранные 1–4 заявки; сравнение 2–4 заявок показывает одинаковые области, язык отдельно и совместимость критериев. Выбор стоимости и отдельный пакетный блок подготовки убраны из очереди.

**Диалог:** один Responses API запрос на сообщение, выбранная владельцем текстовая модель, строгий ответ с точными цитатами, тайм-аут 45 секунд и общий бюджет подключения. Нет локального ответа вместо ошибки, искусственной задержки или запроса разрешения перед каждым обычным сообщением. История и реальное происхождение сохраняются в `ProfileAnswer`; request key не допускает двойной отправки. При неопределённом сетевом исходе повтор восстанавливает тот же запрос. Черновики уточнения и ATOLA используют прежние `DeskAction`, точный предпросмотр и подтверждение. Чат не меняет приёмную оценку, решения и этапы самостоятельно.

**Доступ:** нужны включённый владельцем `deskEnabled`, действующее согласие кандидата и выбранные разрешённые источники. Без выбора заявки возможен общий вопрос о работе комиссии; фактический контекст ограничен максимум 12 последними разрешёнными заявками. Источники, задачи и встречи собираются сервером. Личные проекты, достижения, фото, учебные разговоры, закрытые шкалы и внутренние оценки не отправляются. Чат объясняет доступные факты и помогает сформулировать вопросы, не пересчитывает скоринг. История и цитаты перепроверяются при загрузке и возврате к окну; после изменения или отзыва материала прежний ответ скрывается. Существующий оценочный адаптер и сохранённые человеческие интерпретации не заменены внешней моделью.

**Проверить:** `/admissions` → выбрать две заявки → «Сравнить» или Vision Desk; карточка Ники Левиной → «Цитата и основание» → полный источник; `/admissions/decisions` → последнее решение и история; `/` → фоновая иллюстрация; `/my?view=profile` → монета U. На странице решений последнее действие, основание, автор и статус публикации сгруппированы по кандидату. История не удаляется.

Новых миграций нет. Обычный запуск: `npm run build`, затем `npm start -- --port 3102` с `APP_ORIGIN=http://localhost:3102`. В этой рабочей копии актуальная сборка находится в `.local/desk-release-check`: `NEXT_DIST_DIR=.local/desk-release-check npm start -- --port 3102`. Существующие настройки подключения сохраняются. На момент приёмки `deskEnabled` в рабочей базе выключен: включение и два живых запроса ожидают отдельного разрешения после отказа автоматической проверки разрешений. Проверка с контролируемым транспортом не является полученным ответом GPT.

Главная использует фоновую растровую иллюстрацию вымышленных персонажей; текст и действия остаются HTML. Поинты обозначает рисованная монета U. Оригиналы, WebP и точные промпты двух новых изображений сохранены в `public/images/invision/manifest.json`. Генерация выполнена один раз встроенным image_gen; при открытии сайта вызовов нет. Перед каждым вызовом перепроверяются согласие, владелец и версии. Передаются только выбранный законченный аудиоответ либо требования задания и две расшифровки, без остальной заявки и личных проектов. Локальные скоринг, профиль, Fairness Twin и участники миссий не переключаются сохранением ключа. Сложная текстовая модель и озвучивание доступны отдельным проверкам; новый процесс оценивания не создавался.

**Бюджет.** Исходные $50 внесены вручную; рабочий лимит $45, резерв $5, дневной лимит $5 (UTC), параллельность 2 с выбором 1–3. PostgreSQL атомарно резервирует консервативную стоимость каждого вызова, включая каждый повтор очереди (до 3 попыток). Повтор `requestKey` не выполняет платный запрос. По input/output usage сохраняется расчёт с версией тарифов. Без usage и при сетевой неопределённости остаётся явно обозначенная оценка; токены не придумываются. Короткая проба TTS резервирует $0.10 и сохраняет оценку, поскольку endpoint не возвращает usage. После падения процесса через 2 минуты освобождается только параллельный слот, не зарезервированная стоимость. Нехватка лимита блокирует вызов до отправки, но не сохранение работ. Расходы других приложений не учитываются: это не точный баланс OpenAI и не гарантия против изменения внешних тарифов. Замены модели при ошибке нет.

**Модели проверены по официальным страницам 24.09.2026:** [gpt-5.4-mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [gpt-6-sol](https://developers.openai.com/api/docs/models/gpt-6-sol), [gpt-4o-mini-transcribe](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe), [gpt-4o-mini-tts](https://developers.openai.com/api/docs/models/gpt-4o-mini-tts). Текстовая альтернатива — [gpt-6-luna](https://developers.openai.com/api/docs/models/gpt-6-luna), только по выбору владельца. Доступность аккаунту проверяется отдельно. Endpoint фиксирован на `https://api.openai.com/v1/`; Responses: `store:false`, стандартный тариф, без инструментов. JSON-контекст до 128 КБ, ответ до 2400 токенов, существующий декодер аудио до 3 минут; проба текста — 64 токена, TTS — фиксированная короткая фраза. `store:false` не означает нулевое хранение у внешнего сервиса.

Для GPT-6 используется `prompt_cache_options.mode=explicit` без точек кеширования: неявные записи кеша не создаются. Расчёт всё равно учитывает возвращённые `cached_tokens` и `cache_write_tokens`; резерв покрывает повышенную ставку записи. Основание — [официальная документация кеширования](https://developers.openai.com/api/docs/guides/prompt-caching).

Старые `OPENAI_API_KEY`, `OPENAI_TEXT_MODEL`, `OPENAI_TRANSCRIPTION_MODEL`, `AUDIO_WORKER_ENABLED` больше не управляют подключением. `audio:live` не выполняет запросов и направляет к браузеру. Владельцу не нужны команды или редактирование окружения для управления ключом. `AUDIO_DAILY_REQUEST_LIMIT` остаётся дополнительным ограничением числа аудиовызовов. Обычные тесты используют подменённый транспорт. Набор `tests/connection/settings.test.ts` требует изолированную БД **без владельца подключения** и совпадающий `TEST_ORIGIN`; при существующем владельце он останавливается до изменения настроек.

## Интерактивный профиль и личное развитие · 18 сентября 2026

AI-профиль встроен в «Мой путь», результаты работ, опубликованную обратную связь и карточку комиссии. Он представляет известные сведения, не создаёт модель личности или новый скоринг. Попытки, версии, подтверждённая передача, оценки, ATOLA и публикация используются повторно.

Кандидату доступны вопросы о результате, изменениях выбранной версии, продолжении, связи деятельности с программой, явно сохранённом интересе, переданных материалах, заявке и публикациях. Сотруднику — системная и человеческая интерпретация по области, основания, пробелы, противоречия, состояния до/после уточнения, переданные работы, подготовка и результаты ATOLA. Ввод поддерживает названия этих команд и короткие продолжения: «Почему?», «Покажи источник», «Что дальше?». Неподдерживаемый вопрос просит уточнить контекст. Произвольный текст не анализируется по ключевым словам.

`ProfileProvider` отделён от `AssessmentProvider`: вопрос не запускает оценивание. `PROFILE_PROVIDER=local` использует шаблоны по настоящим серверным полям. Подготовленных профильных историй нет; сохранённый результат скоринга объясняется только в собственной заявке. Другая настройка завершается ошибкой без сети или fallback. Наличие ключа режим не переключает. В `ProfileAnswer` сохраняются реальный адаптер `local`, версия `profile-facts-v1`, хеш контекста, роль, область вопроса, время, источники и их версии. Фиктивных моделей, usage и request ID нет.

Разделение ролей выполняется до сборки контекста. Кандидатский сборщик не читает скоринг, внутренние оценки, заметки и Fairness Twin. Служебный сборщик не читает личные попытки, достижения и планы; работа берётся из подтверждённого snapshot передачи, включённого в отправленную заявку. Каждый запрос и открытие источника повторно проверяют права. Цитата проверяется в доступной версии. PDF без извлечённого текста остаётся материалом, а не прочитанным содержимым.

Новые сведения меняют хеш: прежний ответ обозначается историческим. Удаление источника, отзыв передачи или снятие публикации скрывают зависимые ответ, вопрос и заметку при следующем чтении. API возвращает `private, no-store`; локального хранилища ответов/превью нет, при возврате во вкладку контекст проверяется заново. Интерфейс показывает последние 12 ответов каждого контекста, остальные остаются в БД. Повтор запроса с тем же ключом не создаёт второй ответ.

`DevelopmentStep` сохраняет личный шаг с версией основания, конфигурацией `work-actions-drive-v1`, заметкой и ревизией. Изменение текстового объяснения отмечается для просмотра человеком; совпадение строк не выдаётся за смысловой анализ. Каждая цитата проверяется в собственном источнике. Повтор нажатия идемпотентен, активная пара переиспользуется, новый завершённый проход получает новую запись. Контекст аудита исключён из `scoringView`, сравнений кандидатов и `requireCurrentScoring`, поэтому его нельзя передать в решение, человеческую оценку, ATOLA или публикацию как официальный анализ.

Входы и подготовленные ответы недоступны кандидату; сервер связывает каждый аудит с заявкой и проверяет существующие права. Доход, SupportContext, приватные достижения и новые персональные данные для проверок не собираются. Внешние вызовы отсутствуют. `ScoringRun` хранит вход, канонический SHA-256, адаптер, версии сценария и критериев, время и реальные состояния `QUEUED / RUNNING / COMPLETED / FAILED`. Единый валидатор проверяет девять уникальных областей, допустимую шкалу, источники этой заявки, точные цитаты и версии, достаточность отдельно от оценки, основания противоречий и ограничения операций. Это подсчёт разных эпизодов среди выбранных оснований, не официальная психометрическая или IRT-модель. Без заданной шкалы число отклоняется.

При конфликте сервер не перезаписывает работу: введённый вариант остаётся в форме, можно открыть параллельную версию и явно сохранить свой вариант новой записью с исходной базой сравнения. Внешний AI для этого пути не требуется. Подробные проверки и ограничения — в актуальном разделе `QA.md`.

Модель рассмотрения добавлена миграцией `20260917090000_review_publication`; на существующей базе применяйте неприменённые добавочные миграции командой `npm run db:migrate`. Сброс базы и повторный seed не нужны. Для этого сценария используйте отдельную базу без настроенного подключения; `audio:live` не используется.

1. Новый кандидат сохраняет поля и разрешённые материалы, проверяет обзор и явно отправляет заявку. При отсутствии документа доступно существующее пояснение; ссылка на видео остаётся ссылкой, её доступность не считается проверенной.
2. Сотрудник входит в `/admissions`, открывает заявку и сверяет три блока профиля. В «Карте проверки» отдельно сохраняет связанные источники, просмотр, достаточность, согласованность, пробел и вопрос. Оценка проявления — отдельное человеческое действие по настроенной версии рубрики, без общего балла.
3. В источнике можно отметить точный фрагмент и личное действие, связать его с существующим эпизодом. Дубли описаний объединяются только явно, с причиной; исходные записи сохраняются.
4. Во вкладке «Решение и публикация» сотрудник сохраняет внутренний этап. Запрос кандидату готовится отдельно: наблюдение, уточнение/развитие, следующий шаг и источники. Публикация требует предпросмотра и отдельного подтверждения. Сообщение появляется внутри приложения; email не отправляется.
5. Ответ кандидата в переписке становится новым источником. Исходная отправленная версия не меняется; прежние выводы помечаются для сверки. Запрос исправления факта также хранится отдельно.
6. При решении «Интервью» создаётся существующая запись встречи. План ATOLA содержит пять обязательных секций и редактируемые дополнительные вопросы из шаблонов по явно отмеченному пробелу. «Сохранить подготовку» не завершает встречу. После разговора сотрудник отдельно вводит фактическую дату, ответы пяти секций, наблюдение, итог и подтверждение.
7. После сверки новых материалов сотрудник сохраняет новое решение и публикует обратную связь. История решений, подготовки, результатов и публикаций остаётся доступна. Кандидату не передаются внутренние основания, оценки и результаты интервью.

В текущей локальной базе сохранена новая вымышленная история **Леи Соколовой** (`origin=BROWSER_REVIEW_QA`), которой нет в seed: три решения, два опубликованных сообщения, ответ-уточнение и отдельная завершённая тестовая встреча. Найдите её по имени в очереди. Доступ к тестовому аккаунту записан только в игнорируемом `.local/review-browser-account.json`.

Сборщик фактов находится в `src/lib/data.ts`, проверка версий и серверные операции — в `src/lib/review-service.server.ts`, схемы пяти секций, ограничений и небольшого набора вопросов — в `src/lib/review-contract.ts`. Используются прежние роли, `/api/action`, PostgreSQL, сообщения, файлы и версии; новый backend или framework провайдеров не добавлен.

## Запуск

Нужны Node.js 20.9+ и PostgreSQL с `initdb`, `pg_ctl`, `psql`, `createdb` в PATH. На этой машине проверены Node 20.19.5 и PostgreSQL 18.

```sh
npm ci
npm run setup
npm run dev
```

Открыть http://localhost:3000 (точный `APP_ORIGIN`). `setup` создаёт отдельный локальный кластер в `.local/postgres`, базу `leader_id` на `127.0.0.1:55439`, применяет миграции и 12 связанных кандидатских историй. Существующие данные повторный seed не стирает. Остановка базы: `npm run db:stop`. Остановка приложения: Ctrl+C в его терминале.

Кластер слушает только loopback; локальный trust-доступ предназначен для разработки. Для своего PostgreSQL скопируйте `.env.example` в `.env`, задайте `DATABASE_URL` и выполните `npm run db:migrate`. Для внешней базы не запускайте локальный seed. В обычном окружении `ENABLE_LOCAL_SEED=false`.

Для проверки собранного приложения: `npm run build`, затем `npm start` (порт 3000 должен быть свободен). Для HTTPS задайте `APP_ORIGIN` и `COOKIE_SECURE=true`.

## Устройство

Next.js 16 App Router, React 19, TypeScript, Prisma 6, PostgreSQL, Tailwind 4 и CSS-токены. Точные версии закреплены в `package-lock.json`. Приложение не требует внешнего AI, почтового сервиса или облачного хранилища.

- `src/lib/projects.ts`: версия авторского сценария, строгая схема состояния и пять разных проверок. Пять отдельных компонентов рабочих областей находятся в `src/components/workspaces.tsx`; `ProjectEditor` отвечает за общий сценарий и сохранение.
- `src/lib/security.ts`: непрозрачная cookie-сессия с хешем в БД, scrypt для паролей, серверная роль, проверка владельца, Origin и лимит запросов.
- `src/app/api/action`: серверные операции, optimistic revision, журнал версий, отдельные разрешения и человеческие решения.
- `src/app/api/files`: проверка размера, MIME и сигнатуры; максимум 25 МБ на файл и 150 МБ на владельца. Бинарные оригиналы находятся в PostgreSQL. Приватная выдача с Range для аудио/видео.
- `src/lib/recording-cache.ts`: восстановление незагруженных записей из IndexedDB с ключом пользователя, заявки и вопроса. После подтверждённой привязки файла и при выходе пользователя его буфер удаляется. Выбор файла не запускает загрузку. Пробная запись остаётся локальной.
- `src/lib/ai.ts`: заменяемый серверный интерфейс для объяснения источников. Zod-ответ, проверка ID источников, тайм-аут 8 секунд, лимиты входа и 600 выходных токенов. Внешний провайдер не подключён. Контекстные подсказки сейчас детерминированно используют собственную сохранённую работу и каталог, без фиктивной генерации.
- `prisma/schema.prisma`: связанные пользователи, попытки, версии, заявки, передачи, материалы, эпизоды, источники, исправления, оценки, решения, сообщения, интервью и языковые проверки.

Отправка заявки и присоединение материалов сериализованы блокировкой её строки. Передаётся конкретная подтверждённая версия учебной работы. Отправленная заявка фиксирует поля, ID материалов и снимки передач. Уточнения добавляются отдельными записями; оценка сотрудника кандидатом не перезаписывается. Языковая проверка не изменяет лидерские оценки. Дубли источников одного проекта объединяются эпизодом.

## Технические ограничения

Это самостоятельная локальная поставка. Для реальной приёмной кампании нужны организационно утверждённые требования, роль ответственного за данные, сроки хранения, HTTPS, резервные копии и проверенный процесс выдачи доступа. Сейчас нет email verification, восстановления пароля, SSO, антивирусной обработки, квоты хранилища на всё учреждение и распределённого rate limit. Файлы хранятся в БД, не в объектном хранилище. CSP допускает inline-скрипты и eval для Next dev; перед внешним развёртыванием её нужно настроить с nonce и режимом production.

Расшифровка и содержательная сводка новых ответов подключены к серверному OpenAI API. В этой рабочей копии ключ не задан, внешние запросы не выполнялись; ручное рассмотрение работает. Это не автоматическая языковая оценка или решение о поступлении. Русский интерфейс готов; для казахского предусмотрен тип локали и словарь с fallback, полного перевода нет и неработающий переключатель не показан. Проверка в реальных мобильных Safari/Chrome и на разных микрофонах остаётся отдельной приёмкой.

Старый проект не читался, не копировался и не менялся. Push, merge и deploy не выполнялись.

## Новый аудиоответ и OpenAI

Существующая языковая проверка `/apply/english` использует AudioCapture, Recorder и текущий файловый API. Микрофон запрашивается только кнопкой; проба остаётся локальной. Запись или выбранный файл сначала доступны для прослушивания. «Подтвердить отправку записи» загружает файл и дожидается привязки к вопросу. Восстановление из IndexedDB не включает микрофон, не отправляет файл и не создаёт обработку.

Существующий `SourceProvider` в `ai.ts` отвечает на вопросы по текстовым источникам и не имеет операции распознавания файла. Для этого потока добавлен узкий серверный `AudioProvider` с двумя операциями: расшифровка и структурированная сводка. Файловое хранилище, авторизация, языковая проверка и переписка используются повторно.

1. Зарегистрируйте нового кандидата, откройте заявку и языковую проверку, подтвердите согласие на хранение аудио.
2. Сохраните основной ответ и отдельное уточнение. Завершите языковой ответ и отправьте заявку: до отправки комиссия не читает черновик.
3. При настроенном OpenAI появится отдельное, необязательное согласие `openai-audio-v1`. Сохранение согласия и запуск расшифровки — разные действия. После согласия нажмите «Подготовить расшифровку и сводку».
4. Комиссия открывает ту же карточку: оригинал, исходный текст, сводка, точные цитаты и заключение. Исправление расшифровки добавляет версию; старая сводка явно остаётся рассчитанной по исходному тексту. Можно отклонить замечание с пояснением и перейти в существующую переписку. Обработка не завершает человеческую проверку.

В текущей базе новый файловый проход: `audio.nova@candidate.local` / `AudioPath2026!`, Нова Аудио, `origin=BROWSER_AUDIO_QA`. Файлы выбраны и подтверждены через браузер; модельный результат ей не подставлялся. Отдельная подготовленная история Лины Мир (`origin=PREPARED_AUDIO_QA`, `provider=controlled-fixture`) служит только проверке интерфейса сводки на её собственных фиксированных файлах. Она не является живым результатом OpenAI и не создаётся обычным seed.

### Конфигурация

Владелец настраивает подключение через `/settings/openai`, как описано в начале README. Обработчик очереди работает в Node-процессе Next через instrumentation; оплата разрешена только сохранённым ключом, переключателем владельца, бюджетом и согласием кандидата. Внешний сервис получает законченный файл либо требования задания и две расшифровки. Имя, контакты, школа, лидерские оценки и другие материалы заявки в контекст не входят. Модели фиксируются при постановке задачи; изменение модели требует нового явного запуска кандидатом. Сохранение материалов не зависит от провайдера.

Сервер проверяет структуру, ID источника, вопрос, версию и точное вхождение каждой цитаты. Проверка отсутствующего пункта ссылается на требование и весь соответствующий ответ, без выдуманной цитаты. Совпадение цитаты не доказывает точность интерпретации: сводка показывается для сверки человеком. Таймкоды не создаются. Лидерские оценки, решения и этап интервью не изменяются обработчиком.

Официальная документация проверена 15 сентября 2026: [Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [транскрипционная модель](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe), [текстовая модель](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [обработка данных](https://developers.openai.com/api/docs/guides/your-data), [правила использования](https://openai.com/policies/usage-policies/). `store:false` не является гарантией нулевого хранения внешним сервисом; применяются условия и фактические настройки проекта OpenAI.

### Отдельные проверки аудио

`npm test` использует изолированный провайдер и подмену транспорта в тестах; платных запросов не выполняет. Фиксированные WAV в `tests/fixtures/audio/` созданы локальной озвучкой английского текста, без чужой речи. Ожидаемый текст находится только в тестовых данных и не передаётся реальному распознавателю.

SHA-256 обоих WAV закреплены в `manifest.json`: несовпадение останавливает подготовку контрольной истории до записи в БД. Подготовленный текст не подставляется для изменённого или произвольного файла.

Для проверки откройте `/settings/openai` аккаунтом владельца. Каждый вид запроса запускается отдельно после подтверждения оплаты. Обычные тесты не запускают платные пробы. `audio:live` больше не выполняет запросы.

Для контролируемого виртуального входа: `npm run audio:virtual`, затем `http://127.0.0.1:4177`. Стенд вне продуктовых маршрутов подаёт WAV через Web Audio в настоящий MediaRecorder с тем же AudioCapture. Он не вызывает getUserMedia и не захватывает помещение. Приложение и этот стенд останавливаются Ctrl+C в соответствующих терминалах.
